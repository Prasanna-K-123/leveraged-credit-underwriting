# Exact-period credit bridge — execution review

The trailing twelve-month calculation combines the previous full fiscal year with the current year-to-date amount and removes the matching prior year-to-date amount. A six-month duration filter cannot safely do that for a first- or third-quarter report. This separate API identifies exact fiscal starts/ends and requires an explicit filing cutoff before using any source.

Method was registered at `8f7f5dcca4b72105e9b402acae1b4a5269a6838c` before new execution. It supports unchanged12-month fiscal calendars whose fiscal year/quarter dates fall at month ends. Leap February uses the previous year's actual month-end date. Stale fiscal context, 52/53-week calendars, off-quarter dates and missing exact contexts fail closed. Calendar frames and filing fy/fp are not treated as equivalent to an economic duration.

## Use the separate strict API

```python
from credit_underwriting.period_bridge import build_ttm_metrics_period_aware
metrics, sources = build_ttm_metrics_period_aware(
    companyfacts, latest_10q_report_date, latest_10k_report_date,
    filing_cutoff="2026-10-13", duration_overrides=verified_exact_context_overrides,
)
```

The caller must supply the actual bundle and dates; those variable names are not fabricated issuer data. Required duration observations use USD and exact start/end/form/available filing contexts. A table override must specify the exact interval, consistent USD/millions values, accession-linked SEC Archives URL and64-hex source digest. A legacy override with start=None is refused. These checks validate supplied provenance fields; the pure calculation API does not re-download a document, authenticate its body or establish completeness of historical API revisions. The caller retains and checks raw source bytes and hashes.
